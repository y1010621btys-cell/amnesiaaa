# 接自己的记忆库（回响）

回响 = 她说话时，记忆库里跟这句话沾边的东西「漏」一点出来。**他永远拿不到原文**，只拿到旁白磨过的、模糊的一两句。

## 怎么接

自部署版 `server/config.json`：

```json
"memory": { "url": "http://127.0.0.1:8000/search?q={q}" }
```

`{q}` 会换成她这一句话。POST 的写法、返回格式见 `config.example.json` 和 `server/server.mjs` 里 `memorySearch` 的注释——
返回纯文字就行，JSON 的话会去认 `results / items / data / memories` 里的 `content / text / body / summary`。
接口对不上？让你的 AI 改 `memorySearch` 或者给记忆库包一层，几行的事。

不接也能玩：回响会从「没放进这一夜的底片」和设置里的「更多记忆」里捞（按字面沾边，没有向量）。

网页版接不了（浏览器直接访问别人的记忆库会被跨域拦），要接就用自部署版。

## 参考做法（可以照这些数来）

- 拿**她最新这一句**去搜；少于 4 个字不搜，少于 6 个字不走向量。
- **关键词优先**，最多 3 条；关键词命中不到 2 条，再用**向量补**，相似度门槛 **45**（0–100 的分）。
- 每条最多 **600 字**，交给旁白的素材一共最多 **1500 字**。

## 怎么让回响又少又模糊

不是靠少搜，是靠**旁白**和**掷骰子**：

1. **素材不给他，只给旁白。**旁白按「回响强度」（开局的滑条，0–100）磨：
   - 低于 40：只取一点气味、颜色；
   - 40–74：半帧画面；
   - 75 以上：差一点就想起来。
   一律不带名字、日期、不交代关系；一轮最多一小段（≤400 字）。
2. **碰到底片要掷骰子**：没碰到钥匙时，「这一句让某块底片闪一下」的概率 = 回响强度 ÷ 100 × 难度系数
   （轻 0.7 / 默认 0.5 / 难 0.3 / 很难 0.15），一句最多动一块，自动最多升到「画面」（难和很难只到「感官」）。
3. 想更少？门槛调高（比如 55）、只取 1 条、或者搜之前也掷一次骰子——都在 `memorySearch` / `echoMaterial` 里改。
